# Trip Atlas

Next.js + TypeScript로 만든 엑셀 기반 여행 장소 정리 앱입니다. 로그인한 계정의 장소만 볼 수 있으며 Supabase의 계정별 비공개 DB에서 불러옵니다. Google Maps 키를 연결하면 Google 지도를 사용하며, 연결 전에는 OpenStreetMap으로 표시합니다.

배포 주소: https://trip-xi-rosy.vercel.app

Vercel Hobby와 서울 리전의 Supabase Free(`trip-db`)를 연결했습니다. GitHub `main` 브랜치 변경은 Vercel에서 자동 배포됩니다. 원본 엑셀, 환경변수, 로컬 도구 파일은 Git 및 배포 대상에서 제외됩니다.

## 실행

Node.js 22 이상에서:

```sh
npm install
npm run dev
```

http://localhost:3000 에서 엑셀 가져오기를 누르고 `01_instagram_DM_hongkong.xlsx`를 선택하세요. 장소목록 시트의 제목 행을 자동으로 찾아 156개 항목을 읽습니다. 원본 엑셀은 수정하지 않으며, 개인 DM 시트는 읽어 앱에 저장하지 않습니다. 원본 파일은 Git과 배포에서 제외됩니다.

일반 파일은 첫 시트에 `장소명` 또는 `장소·상호` 열이 필요합니다. 주소, 지역, 분류, 위도, 경도, 메모 열은 선택입니다. .xlsx 형식, 최대 10MB/5,000개 장소를 지원합니다. 동일 이름·주소·지역은 재가져오기 시 중복 제외되며 기존 메모를 유지합니다. 내보내기는 Excel에서 열 수 있는 UTF-8 CSV입니다.

## Instagram에서 장소 / 정보 추가

상단의 **Instagram 추가**에서 릴스 URL만 입력하고 **릴스 분석**을 누르세요. 공개 설명을 읽고 **장소 / 여행 정보**로 분류한 결과에서 저장할 수 있습니다. 처음부터 설명·장소명·주소를 입력할 필요는 없습니다.

- 서버가 공개 페이지의 JSON-LD와 미리보기 설명을 읽습니다. API 키나 유료 AI 서비스 없이 설명 패턴을 기준으로 분류합니다. 영상·자막·음성을 분석하는 기능은 아니며 비공개·로그인 필요·접근 제한 등으로 설명을 읽지 못할 수 있습니다.
- `장소명:`, 핀 이모지의 상호명, 주소가 붙은 번호 목록, 상호 아래의 지점별 주소를 장소 후보로 분리합니다. 이름·주소가 드러나지 않는 설명은 여행 정보로 보관합니다. 자동 분류는 결과 화면에서 변경할 수 있습니다.
- 여러 장소는 선택해 한 번에 저장합니다. 출처와 주소가 같은 기존 장소는 기존 이름·메모·좌표를 유지하고 설명을 연결합니다. 같은 릴스의 여행 정보도 중복 생성하지 않습니다.
- 읽지 못한 릴스는 내용을 만들어 넣지 않고 **확인 대기 링크 저장**으로 보관합니다. 필요할 때 **기존 항목에 연결 / 설명 수정**에서 설명을 붙여 넣고 다시 분류할 수 있습니다.
- 여행 정보는 `kind: information`으로 저장되며 지도 마커와 위치 지정 대기 개수에서 제외됩니다. 목록의 **장소·정보 필터**에서 따로 볼 수 있습니다. 기존 엑셀 데이터와 Supabase JSONB 스키마를 그대로 사용하며, 클라우드 저장은 기존처럼 사용자가 눌렀을 때 반영됩니다.
- 좌표는 장소 편집에서 확인·지정합니다. 게시물 설명만으로 정확한 좌표를 생성하지 않습니다.

`POST /api/instagram`은 HTTPS Instagram 릴스 URL만 허용하고 외부 리디렉션을 따라가지 않습니다. HTML은 텍스트로만 처리하며 응답 크기/시간을 제한합니다. 캐시와 분당 15회 요청 제한은 서버 프로세스 단위이므로 대규모 공개 서비스에는 공용 캐시와 요청 제한을 추가하세요.

## 지도와 좌표

### Google 지도 연결

1. Google Cloud에서 **Maps JavaScript API**를 활성화하고 결제 계정을 연결합니다. 기존 브라우저용 API 키를 사용할 수 있습니다.
2. `.env.local`에 `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=키값`을 추가합니다. 이 값은 브라우저에 노출되는 공개 키이므로 Google Cloud의 웹사이트 제한과 API 제한으로 보호합니다. API 제한은 Maps JavaScript API로 지정하세요.
3. 허용 웹사이트에 `http://localhost:3000/*`, `http://localhost:3001/*`, `http://127.0.0.1:3001/*`, `https://trip-xi-rosy.vercel.app/*` 등 실제 사용하는 주소만 추가합니다.
4. 고급 마커용 JavaScript 지도 ID를 만들면 `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID`에 지정합니다. 생략하면 로컬 테스트용 `DEMO_MAP_ID`를 사용합니다. 운영 배포에는 본인 프로젝트의 지도 ID를 권장합니다.
5. 개발 서버를 재시작합니다. 배포 시에는 Vercel 환경변수에도 같은 값을 등록하고 다시 빌드해야 합니다. `NEXT_PUBLIC_` 값은 빌드 시 결정됩니다.

지도 핀 선택, 선택한 장소 강조, 목록 필터에 맞춘 지도 범위, 지도 클릭으로 위치 지정을 지원합니다. 네트워크/인증 오류가 나면 OpenStreetMap으로 전환할 수 있습니다. 지도 선택과 메모 편집만으로 새 지도를 생성하지 않습니다.

Google Dynamic Maps는 월 10,000회 로드까지 무료이며 이후 사용량에 따라 청구됩니다. Places·경로 API는 이 구현에서 호출하지 않습니다. [요금표](https://developers.google.com/maps/billing-and-pricing/pricing), [API 키 제한](https://developers.google.com/maps/api-security-best-practices)을 확인하세요. 예산 알림은 비용을 차단하는 기능이 아닙니다.

### 월간 Google 지도 차단

- 새 Google 지도를 생성하기 **전에** `/api/maps/reserve`에서 사용 횟수를 예약합니다. Supabase의 원자적 업데이트로 모든 사용자·기기·개발/운영 서버의 합계를 집계하여 **9,899회까지만 허용하고 9,900번째부터 차단**합니다. 필터·마커 선택·지도 이동은 새 로드로 세지 않습니다.
- 차단되거나 DB·서버·네트워크 오류가 나면 Google 지도를 생성하지 않고 OpenStreetMap으로 표시합니다. 한 번 예약한 횟수는 지도 로드가 실패해도 돌려주지 않아 보수적으로 집계합니다. React 개발 모드의 effect 재실행은 같은 예약을 재사용합니다.
- 월 구분은 Google 무료 사용량과 같은 미국 태평양 시간(`America/Los_Angeles`)을 따릅니다. 다음 달에는 새 집계 행을 사용합니다. 월말 마지막 30초는 차단하며, 허가는 15초 내 지도 생성에만 사용합니다.
- Supabase SQL Editor에서 `supabase/map-budget.sql`을 실행하고 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`를 설정합니다. 테이블과 예약 함수는 `anon`/`authenticated`에 공개하지 않으며 서버에서만 호출합니다. 키는 절대 `NEXT_PUBLIC_`로 만들지 마세요. 기존 Vercel Supabase 연결은 이 서버 키를 제공합니다.
- 초기에는 **비활성화** 상태입니다. 관리자만 이번 달 기존 Dynamic Maps 사용량을 확인해 `google_map_monthly_usage`의 현재 월 `loads`에 반영한 뒤 `google_map_budget_settings.enabled`를 켭니다. 이미 예약된 값을 낮추거나 월별 행을 삭제하면 차단 보장이 깨집니다.

이것은 **이 앱에서 예약하는 지도 로드의 상한**이며 Google의 청구 상한이 아닙니다. Google 무료 한도는 동일 결제 계정의 다른 프로젝트 사용량과 합산됩니다. 기존 사용량, 다른 앱, 공개 키를 이용한 직접 호출은 이 카운터로 자동 파악/차단할 수 없습니다. 전용 프로젝트/키와 웹사이트·API 제한을 함께 사용하고 Google 콘솔 사용량을 확인하세요. 브라우저 키 공개 동의와 배포 절차는 별도입니다.

### 내 Google 지도에서 보기

상단 **내 Google 지도로**에서 My Maps용 CSV를 받습니다. 필터와 관계없이 전체 목록의 유효한 좌표가 있는 장소만 포함하며, 장소명·설명·메모·방문상태·희망일·위치 정확도·출처를 보존합니다. 위치 미지정과 여행 정보는 제외됩니다. 2,000개를 넘으면 파일을 나눠 각각 다운로드할 수 있습니다.

Google [내 지도](https://www.google.com/maps/d/)에서 새 지도 → 가져오기 → CSV를 선택하고 위치 열은 **위도/경도**, 제목 열은 **장소명**으로 선택합니다. 동일 계정의 Google 지도 앱의 **나 → 지도**에서 볼 수 있습니다. 일반 ‘가고 싶은 곳’ 저장 목록과는 별도이며 자동 동기화하지 않습니다. 앱에서 수정한 뒤 CSV를 다시 가져와 ID 열로 일치시켜 갱신하세요. 지도 공유 범위는 My Maps에서 설정합니다.

개별 장소 편집의 **Google 지도에서 열기**는 API 키 없이 이용할 수 있습니다. Google 지도에서 직접 저장하거나 길찾기를 실행할 수 있습니다.

### 좌표 찾기

엑셀에 유효한 위도·경도가 있으면 즉시 핀을 표시합니다. 현재 홍콩 엑셀에는 좌표가 없으므로 장소 편집에서 주소를 검색해 후보를 선택하거나 지도에서 위치를 직접 지정하고 저장하세요. 좌표를 추측해 넣지 않습니다. 검색은 명시적으로 버튼을 누를 때만 Nominatim에 요청하며, 자동완성이나 일괄 주소 변환은 하지 않습니다. 검색어는 외부 검색 서비스로 전송됩니다.

- [OpenStreetMap 타일 정책](https://operations.osmfoundation.org/policies/tiles/)
- [Nominatim 이용 정책](https://operations.osmfoundation.org/policies/nominatim/)

공개 Nominatim은 서비스 전체 최대 1요청/초 정책이 있습니다. 이 앱의 브라우저별 제한은 여러 사용자 전체를 제한하지 못합니다. 소규모 개인 이용에 맞춘 구현이며 공개·다중 사용자 확장 시 중앙 요청 제한/캐시 또는 별도 지오코딩 제공자로 전환해야 합니다. 타일은 일반 온라인 보기만 사용하며 대량 다운로드/오프라인 저장을 하지 않습니다.

## 무료 DB 연결

1. Supabase에서 Free 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/schema.sql`을 실행합니다.
3. `.env.example`을 `.env.local`로 복사해 Project URL과 publishable/anon 공개 키를 넣습니다. **service_role 비밀 키는 넣지 마세요.**
4. Authentication의 이메일 로그인을 활성화하고 실제 배포 주소를 Site URL/Redirect URL에 등록합니다.
5. 개발 서버를 다시 시작하거나 배포를 다시 빌드합니다.

앱을 열면 로그인 화면만 표시합니다. 로그인 상태를 Supabase `getUser()`로 확인한 뒤 계정의 DB 목록을 자동으로 불러옵니다. 로그인 전·인증 확인 중에는 장소·지도·업로드·내보내기를 렌더링하지 않습니다. 로컬 엑셀 자료를 페이지 HTML에 포함하지 않으며, 이전 공용 localStorage 목록도 자동으로 가져오지 않습니다. 이전 브라우저 자료는 삭제하지 않지만 새 계정으로 자동 이전하지 않습니다.

RLS로 로그인한 사용자의 행만 읽고 쓸 수 있습니다. 새로 추가하거나 편집한 내용은 화면 메모리에 유지되며 **내 계정 → 현재 목록 클라우드에 저장**을 눌러야 DB에 반영됩니다. 저장 전 페이지를 떠나거나 로그아웃하면 경고합니다. 로그아웃·계정 변경 시 목록·지도·편집 화면을 제거하고, 이전 계정의 늦게 도착한 DB 응답은 버립니다. 새 계정에 저장된 목록이 없으면 빈 목록으로 시작합니다. 동시 공동 편집은 지원하지 않습니다.

Supabase Free 한도와 휴면 정책은 [공식 요금제](https://supabase.com/pricing)를 확인하세요. 무료는 무제한을 뜻하지 않습니다.

## 무료 배포

표준 Next.js 프로젝트이므로 Vercel에 가져올 수 있습니다. 개인·비상업 프로젝트에는 [Vercel Hobby](https://vercel.com/docs/plans/hobby)를 사용할 수 있습니다.

1. 이 프로젝트를 자신의 GitHub 저장소에 올립니다. 원본 엑셀과 `.env.local`은 제외됩니다.
2. Vercel에서 저장소를 Import하고 Next.js 프레임워크로 배포합니다.
3. 환경 변수에 위 Supabase 공개 값 두 개를 추가하고 다시 배포합니다.
4. Supabase 인증 URL을 배포 주소로 설정합니다.

Instagram URL 정보를 읽는 서버 API를 사용하므로 일반 Next.js 배포가 필요합니다. `npm run build` 후 `npm start`로 실행하며, Vercel에서는 Next.js 기본 빌드 설정을 사용하세요. 예전 정적 `out/` 결과는 이 기능을 포함하지 않으므로 배포하지 마세요. Google 지도를 사용하려면 위 Google Maps 환경변수도 등록합니다. 배포에 장소/DM 원본은 포함되지 않으며 사용자가 파일이나 URL을 가져와 저장합니다.

## 검증

로컬 개발에서는 임시 계정을 만든 뒤 `admin / admin`으로 로그인할 수 있습니다. `/api/auth/local-admin`은 개발 모드·localhost·동일 출처 요청에만 동작하며, Git/Vercel에서 제외된 `.local-data/admin-account.json`의 기존 계정으로 정상 Supabase 인증을 수행합니다. 운영 빌드에서는 404로 차단됩니다. 원래 비밀번호는 변경하거나 클라이언트에 반환하지 않습니다. 일반 이메일 로그인은 기존대로 동작합니다.

```sh
npm run typecheck
npm test
npm run build
```

실제 엑셀 검증 테스트에는 작업 폴더의 원본 파일이 필요하며, Git에 포함하지 않는 파일이므로 원본이 없는 환경에서는 해당 테스트만 건너뜁니다. 나머지 테스트는 그대로 실행됩니다. 외부 인증·DB 검증에는 자신의 Supabase 설정이 필요합니다.
